# Shopee Research

スマホのChromeで利用できる、日本語の商品利益リサーチ試作版です。外部API・アカウント・データベースは不要です。URLからの情報取得、最新為替の取得、Shopee公式料金の自動反映は行いません。

## 起動

Node.js 20以上で、リポジトリ内から実行します。アプリの実行自体にはnpm依存パッケージのインストールは不要です。

```sh
npm start
```

ポート3000、全インターフェースでHTTPを待ち受けます。変更する場合は `PORT=3001 npm start` を使用してください。終了は Ctrl+C です。ローカル開発時にスマホから利用する際は、スマホから到達可能なサーバーのアドレスまたは利用環境のポート共有機能を使ってください。スマホ自身のlocalhostではこのサーバーには接続できません。固定URLへの公開は以下のGitHub Pages手順を使用します。

## GitHub Pagesで固定URLに公開

対象は **infinitelmiw-dev/shopee-research のみ**です。monomikke・推しスマなど他リポジトリへの操作は不要です。GitHub PagesではNodeサーバーを動かさず、静的ファイルだけで計算・localStorage保存を行います。

公開成功後の標準URL（カスタムドメイン未設定の場合）：

**https://infinitelmiw-dev.github.io/shopee-research/**

設定ファイルを追加しただけでは公開されません。以下のpush・mainへのマージ・GitHub Pages設定とActionsの成功が必要です。

### 1. GitHubの公開設定

対象リポジトリ https://github.com/infinitelmiw-dev/shopee-research の **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。Actionsが無効ならこのリポジトリで有効化してください。設定権限がなければ管理者にこのリポジトリの設定を依頼します。

リポジトリが非公開の場合、利用プラン／組織ポリシーによってPagesの利用可否が異なります。Pagesが使えない場合は契約・組織設定を確認してください。この手順でリポジトリの公開範囲を変更する必要はありません。公開したサイトとそのJavaScriptは通常誰でも閲覧できます。ログイン機能はありません。

### 2. このリポジトリの変更だけをGitHubへ反映

以下はこのクラウド環境の作業ディレクトリで実行する例です。手元のPCの場合は先に修正済みファイルを同じリポジトリへ取り込んでください。トークンや秘密情報をコマンドへ貼り付ける必要はありません。

```sh
cd /workspace/shopee-research
git status --short
git remote get-url origin
# originが infinitelmiw-dev/shopee-research であることを確認
git switch -c publish-shopee-pages
git add .gitignore .github/workflows/pages.yml README.md package.json package-lock.json index.html style.css app.js calculator.js server.js scripts tests
git diff --cached --check
git diff --cached --stat
git commit -m "Build Shopee research app and configure GitHub Pages"
git push -u origin publish-shopee-pages
```

GitHubで `publish-shopee-pages` から `main` へのPull Requestを作成し、変更対象を確認してマージします。同名ブランチが既にある場合は別のブランチ名を使ってください。force pushや他リポジトリへの変更は不要です。

### 3. 公開の完了を確認

**Actions → Deploy Shopee Research to GitHub Pages** を開き、`build` と `deploy` が両方成功したことを確認します。ワークフローは `main` へのpushで自動実行され、手動の **Run workflow** でも起動できます。手動起動時も `main` を選んでください。Pagesの公開先ブランチ規則によって他ブランチからの公開は拒否される場合があります。

ビルドは依存導入、計算テスト、公開ファイルの組み立てと秘密情報パターン検査、360px／390pxの公開成果物テストを実施し、成功した場合だけ `dist/` を公開します。`deploy` の環境欄に表示されるURLが実際の公開URLです。404のままの場合はActionsの失敗ログとSettings → PagesのSourceを確認してください。ローカルテストの成功だけではGitHub上のデプロイ成功は保証されません。

### 4. スマホChromeで確認

1. 通常モードのChromeで上記の **末尾が `/shopee-research/` の固定URL** を開き、ブックマークします。
2. 全8費用欄が表示され、横スクロールなしで入力できることを確認します。
3. 販売価格100 SGD・レート110、仕入れ5000円・国内送料500円・国際送料1000円・梱包100円・販売手数料10%・決済手数料3%・為替費用2%・返品損失100円、採用基準500円／20%を入力します。利益 **2,650円**・利益率 **24.09%**・**採用候補** が目安です。
4. 料金設定を保存し、ページを再読み込み／タブを閉じて同じブックマークを開きます。商品URLや費用も復元され、同じ利益になることを確認します。
5. 国際送料を空欄にして「判定保留」、0にして計算再開を確認します。「最後の入力欄に戻る」と「新しい商品を調べる」のキャンセルも確認できます。

プレビューからPagesへ移るとオリジンが変わるため、**プレビュー内の保存済み入力・設定は自動移行しません**。必要な数値を控え、Pagesで初回入力・保存してください。その後は同じ端末・Chromeプロファイル・固定URLを使えば、通常の再デプロイでは保存領域は変わりません。ブラウザデータ削除、シークレットモード終了、ドメイン変更などでは復元を保証できません。localStorageはパス単位ではなくドメイン等のオリジン単位なので、同じ `infinitelmiw-dev.github.io` 上のサイトとは保存領域を共有します。本アプリは `shopee-research.*` キーだけを操作します。

### 公開対象と秘密情報確認

`npm run build` は `dist/` に **index.html・style.css・calculator.js・app.js・空の.nojekyll** だけを組み立てます。Actionsはリポジトリ全体をサイトとしてアップロードしません。テスト、サーバー、README、node_modules、スクリーンショット、キャッシュ、.git、.envや鍵ファイルは公開成果物に入りません。`.env`・`.env.*`・`*.pem`・`*.key` はGitの無視対象にもしています。

公開前の確認コマンド：

```sh
npm ci --cache .cache/npm
npm run build
npm run check:public
npm test
npm run test:pages
```

`test:pages` にはChromiumが必要です。このクラウド環境では `/usr/bin/chromium` を使用します。別環境では `npx playwright install chromium` で導入するか、`CHROMIUM_PATH` を指定してください。GitHub Actionsは必要なChromiumを導入します。

公開対象の許可リストに加え、秘密鍵・GitHubトークン・AWSアクセスキー・APIキー・認証情報入りURL等のパターンを検査します。今回、作業ツリーのソース／設定と既存Git履歴も確認し、該当する秘密情報は検出されませんでした。パターン検査は未知の形式や任意の機密情報すべてを保証するものではないため、今後追加する値もcommit前に確認してください。GitHub Actionsには標準の短期トークンを使用し、独自のAPIキーやPATの登録は不要です。ブラウザのlocalStorageにある実入力はGitのファイルや公開成果物に含まれません。

## 使い方と計算

1. 商品URL（任意）、想定販売価格、通貨コード（SGD・USD・JPYなど3文字）、1通貨あたりの円レートを入力します。JPYは1固定です。
2. 仕入れ価格、国内送料、国際送料、梱包費を1商品あたりの日本円で入力します。
3. 販売手数料・決済手数料・為替費用・返品損失見込みを、円額または円換算販売価格に対する割合（0〜100%）で入力します。返品損失は1商品あたりの期待損失です。固定額と割合を併用したい場合は合計を円額で入力してください。
4. 最低利益額と最低利益率を設定します。初期基準は500円・20%で、事業上の推奨値ではありません。

利益額 = 想定販売価格 × 為替レート − 全8項目の費用合計。
利益率 = 利益額 ÷ 円換算販売価格 × 100。
両方の基準以上なら「採用候補」、どちらかが未達なら「見送り」です。表示は小数第2位まで、判定は丸める前の数値で行います。

**不明な費用は空欄にしてください。** 明示的な0とは区別され、空欄・不正値があれば利益額／利益率を表示せず「判定保留」と理由を表示します。販売価格と為替レートは正数、費用と基準は0以上の半角数値を使用します（桁区切りカンマは不要）。税金など追加費用は対応する費用に含めてください。

商品URL・販売価格・仕入れ価格・送料・梱包費・各手数料・為替費用・返品損失、各費用の円/%単位、通貨・為替レート・採用基準を、変更のたびにlocalStorageへ自動保存します。再読み込み・プレビュー再表示時は直前の入力を復元し、利益と判定を再計算します。保存時には文字列をそのまま保持するため、空欄と「0」は区別されます。作業中の商品1件を保持する仕組みで、商品履歴はありません。自動保存の成否は画面上部に表示します。保存が拒否された場合もその場の計算はできますが、再表示時の復元はできない可能性があります。

「最後の入力欄に戻る」で、最後に編集した項目へ移動してフォーカスできます。再表示直後にキーボードが勝手に開かないよう、移動はボタンを押した時に行います。

「現在の料金・為替・基準を保存」は、仕入れ価格を除く7費用と単位、通貨・レート・基準を**新しい商品の初期設定**として保存します。既存の保存キー `shopee-research.settings.v1` を維持し、作業中の商品は別キー `shopee-research.product.v1` に保存します。自動保存や商品初期化で保存済み設定を上書き・削除しません。初回は保存設定を適用し、商品入力が保存されていればそちらを優先します。未保存の基準変更も作業中の商品として復元しますが、新商品の初期設定は保存ボタンを押すまで変わりません。

「新しい商品を調べる」は確認ダイアログを表示します。キャンセルすると入力を維持します。確定するとURL・販売価格・仕入れ価格を空欄にし、他の費用と単位を保存済み料金へ戻します（保存設定がなければ空欄・円）。現在の通貨・為替レート・採用基準と保存済み設定は維持します。初期化後の商品入力も保存するため、再読み込みで前の商品が復活することはありません。保存に失敗した場合は、その旨を画面に表示します。

**保存領域の制約：** 復元できるのは、同じ端末・ブラウザプロファイル・保存領域を使う場合です。localStorageはオリジン（通信方式・ドメイン・ポート）ごとに分かれます。プレビューURLの変更でオリジンが変わる場合、埋め込み先などによって保存領域が分離される場合、閲覧データ削除やシークレットモード終了時は復元を保証できません。同一オリジンのパス・クエリの変更だけなら通常は同じ保存領域です。別端末への同期・URLをまたぐ移行・バックアップはありません。

入力データを外部に送信する処理はありません。外部フォントやCDNも使用しません。

## 検証

```sh
npm test
```

Node標準テストで換算・割合費用・全費用の空欄と0・境界値・赤字・不正値・オーバーフローを検証します。

ブラウザテストにはPlaywrightとChromiumを使用します。別ターミナルで `npm start` を起動したうえで実行してください。

```sh
npm ci --cache .cache/npm
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

Chromiumの配置が異なる場合は `CHROMIUM_PATH` を変更してください。モバイル相当の入力・保存／復元・保存失敗・JPY固定・幅320〜1280pxでの横はみ出し・外部リクエスト不在を確認します。360pxと390pxでは全8費用の表示・編集・計算への反映、各項目の空欄と0の区別も個別に検証します。商品自動保存についても両幅で、全入力の復元・タブを閉じてからの再表示・入力欄への移動・初期化の確定/キャンセル・既存設定の保持・JPY復元・採用/見送り/保留・ストレージエラーを検証します。画像は `artifacts/mobile-360.png` と `artifacts/mobile-390.png` などに保存します。実機Android Chromeでの検証は別途必要です。

## プレビュー表示の対策

費用欄はHTML内に常設し、JavaScriptによる動的な生成には依存しません。CSS・JavaScriptは相対パスで読み込み、サブパスのプレビューにも対応します。計算処理は順序を指定した通常のdeferスクリプトで読み込みます。スマホの文字自動拡大を抑え、グリッドの最小幅と折り返しを明示しています。入力文字は16px、操作欄の高さは44px以上を維持します。

スクリプトが読み込めない場合も全8項目の費用欄を表示し、画面上部に計算未実行の案内を残します。ブラウザテストではアプリスクリプトの読み込み失敗とJavaScript無効の両方で欄が欠落しないこと、およびサブパスから読み込んでも利益計算が動くことを検証します。
